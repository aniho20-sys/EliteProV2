## 1. i18n 方案 + bundle 影響

實測咗兩條路（數字係喺呢個 repo 度量返嚟，唔係估）：

| | A：i18next + react-i18next | B：自家 `t()` |
|---|---|---|
| 新增依賴 | 2 個（i18next 26.4.1、react-i18next 17.0.13） | **0** |
| Bundle（gzip） | **+13.6KB**（i18next umd min）+ ~0.3KB | **< 1KB** |
| 對比主 chunk（87.5KB gz） | +15% | +1% |
| 複數 / ICU / namespace / lazy load | 全部有 | 複數用 `_one` / `_other` 兩條 key；lazy load 用 `import()` |
| 中文字典（第一階段 ~200 句） | ~3KB gz，lazy | ~3KB gz，lazy |
| 日後升級 | — | 字典格式係 i18next JSON 嘅子集，要換嘅時候係機械式搬遷 |

**建議：B。** 理由：

1. 得一對語言，中文冇複數，i18next 嘅功能九成用唔着，但 13.6KB 係全部人（包括淨用英文嘅）都要落。
2. 零依賴 —— 同 #29 同一種思路：唔好為未用到嘅嘢引入日後會壞嘅嘢。
3. 字典格式刻意跟 i18next 慣例（`{name}` 插值、`key_one` / `key_other`），第三階段真係需要 ICU 嘅話，換引擎唔使改字典。

**設計：**

```
src/i18n/
├── LanguageContext.jsx   — { lang, setLang, t }；lang 由 Firestore 讀，未有就用瀏覽器語言
├── en.js                 — 唯一真相，所有 key 必須喺度
├── zh-HK.js              — 只放已翻譯嘅 key；冇嘅自動 fallback en
└── format.js             — formatDate / formatWeekday 等，locale 跟 lang
```

`t('dash.sessions_left', { n: 7 })` → en `"7 sessions left"` / zh `"剩餘堂數 7"`。

英文用戶：`zh-HK.js` 一個 byte 都唔會下載（`lang === 'zh-HK'` 先 `import()`）。

> 附帶發現：`dist/assets/es-*.js` 有 420KB（175KB gz），係 pdf-lib，已經係 lazy chunk，冇問題。講出嚟係想講清楚 i18next 嘅 13.6KB 唔係「相對好細」—— 佢係落主 chunk 嘅，同 pdf-lib 唔同性質。

## 3. 架構上點確保術語唔會被誤翻

唔靠「記得唔好譯」。三重隔離：

**3.1 `t()` 只接受字面 key，永遠唔接受變數。**
`t('dash.title')` ✅ ｜ `t(exercise.name)` ❌ lint error。
用 ESLint `no-restricted-syntax`（唔使裝新 plugin）：

```js
selector: "CallExpression[callee.name='t'] > :first-child:not(Literal)"
message: "t() takes a literal key. Data (exercise names, plan names, tags) is never translated."
```

`resolveExerciseName()`、`formatSet()`、`plan.name` 呢啲 render 出嚟嘅係數據，佢哋根本冇路經過 `t()`。

**3.2 字典 namespace 就係「可以譯嘅嘢」嘅白名單。**
`nav.*` `dash.*` `booking.*` `plans.*` `profile.*` `common.*`。**刻意冇** `exercise.*` / `muscle.*` / `unit.*`。有人想加，PR review 一眼見到。

**3.3 一條 test 做守門：** 走一次 `data/exercises.js` 全部動作名 + 肌群 + 器材 + pattern + unit 標籤，斷言**冇一個**出現喺 `zh-HK.js` 嘅 key 或者 value 入面。有人手多翻譯咗 "Squat" → 「深蹲」，test 即刻紅。

## 4. 中文長度會唔會爆 layout？

**先講結論：闊度風險低，字體風險高。** 中文一般比英文短 40–60%（「Book Session」→「預約課堂」，「Remind me later」→「稍後提醒」），所以 overflow 唔係主要問題。

**真正高風險嘅係字體：**

| 風險 | 點解 | 建議 |
|---|---|---|
| **字體 fallback** | `Inter` 同 `Bricolage Grotesque` 都**冇中文字形**。中文會跌落 iOS 系統字（PingFang HK），同一行英數字用 Inter、中文用 PingFang，baseline 同 x-height 唔同，會見到「跳」 | 兩個 font stack 都加 `'PingFang HK', 'Noto Sans TC'` 落 Inter 後面。iOS 內置 PingFang，唔使下載 |
| **卡標題** | `.card-title` 用 `--font-display`（Bricolage，粗、有性格）。中文 fallback 後同英文標題風格對唔上 | 同上；另外 zh 模式下 display 字重用 700 唔用 800（PingFang 800 會糊） |
| **33 個 `text-transform: uppercase` 微標籤** | 對中文係 no-op；`letter-spacing: 0.5px` 落 0.7rem 中文會略鬆 | 可以接受；如果真機睇落唔妥，加 `:lang(zh) { letter-spacing: 0 }` |
| **行高 / 固定 56px 行** | 中文字形比拉丁字高少少，compact row 兩行 0.7rem meta 有機會頂 1–2px | 低風險，真機驗 |

**中文反而更長嘅位（要逐個睇）：** 英文縮寫。「PRs」→「個人紀錄」（4 字 ≈ 2× 闊）。ClientDashboard 個 4 格 stat strip 喺 390px 每格約 85px，「個人紀錄」0.7rem 約 45px，OK。「RPE」「kg」「reps」按你嘅規則唔譯，冇呢個問題。

**第一階段最高風險三個位置：**
1. **Booking 日期條** —— `d.toLocaleDateString('en', { weekday: 'short' })` 出 "Mon"；zh-HK 出「週一」（2 字）定「一」（1 字）要揀，影響格闊
2. **首頁問候** —— "Morning, Ani" → 「早晨，Ani」；標點同中英混排
3. **RenewalPromptModal 兩個並排掣** —— 中文短咗反而要睇會唔會兩個掣變得太細

以上全部要真機睇（#36），mock render 只可以睇闊度，睇唔到 PingFang 實際 rendering。

## 5. 日期／數字本地化

**日期 —— 4 個 hardcode 位：**

| 位置 | 而家 | zh-HK 會出 |
|---|---|---|
| `dateUtils.formatDayDate` | `'en-US'` → "Wed 10 June" | 「6月10日週三」 |
| `SchedulePage:77` | `'en'` → "August 2026" | 「2026年8月」 |
| `SchedulePage:345` | `'en'` → "Mon" | 「週一」 |
| `SchedulePage:411` | `'en'` → "Thursday, August 27" | 「8月27日星期四」 |

做法：全部收去 `i18n/format.js`，locale 由 context 攞，`Intl.DateTimeFormat` 原生支援 `zh-HK`，唔使額外 library。（上表嘅 zh-HK 輸出係喺 Node 實際跑過 `Intl` 得出，唔係估。）**儲存格式 `YYYY-MM-DD` 一個字唔改**（#18），只係顯示層。

**時間：** 已經係 24 小時制 `HH:MM`，中英一樣，唔使郁。

**數字：** 堂數係細整數，冇千位分隔問題。

**貨幣：** `formatCurrency` 用 `en-GB`。試過 `zh-HK`：HKD 出 "HK$1,200.00"、GBP 出 "£1,200.00" —— **同 en-GB 一模一樣**。建議**唔郁**，慳返一個 #31 嘅風險位。

**Firebase Auth 電郵（密碼重設等）：** 唔使譯。Client SDK 設 `auth.languageCode = lang` 之後，Firebase 內置 template 自動出 zh-TW（Firebase 冇 zh-HK，只有 zh-TW，繁體用字接近）。⚠️ **條件：Console 入面 template body 冇被自訂過。** 你早排改咗 sender name —— 淨改 sender name 唔影響；如果改埋 body 就會變單語。呢個要你去 Console 望一眼。App 自己出嘅 `mail` collection 電郵只係俾你嘅註冊通知，唔係用戶見到嘅，唔譯。

## 7. 點防止漏字串（顯示原始 key）

「顯示原始 key」呢個 bug 冇 error、test 捉唔到 —— 前提係你靠**人**捉。改成三層機械檢查，每層針對一種漏法：

| 層 | 捉咩 | 點做 | 幾時響 |
|---|---|---|---|
| **L1 Lint** | 「忘記包 `t()`」—— 頁面度直接寫英文 | `eslint-plugin-react` 嘅 `react/jsx-no-literals`，**只對已翻譯嘅檔案**開（eslint flat config 嘅 `files:` glob）。要裝 1 個 devDependency | commit 前 |
| **L2 Test** | 「key 唔存在」—— 打錯 key、改名漏改 | vitest 用 regex 掃晒全 src 嘅 `t('…')`，逐條斷言存在於 `en.js` | `npm test` |
| **L3 Runtime** | 剩返嘅 | `t()` 搵唔到 key：DEV `console.error` + 回傳 key（等你開發時見到）；**PROD 永遠回傳 en**，en 都冇就回傳空字串 —— **無論如何唔會 render 原始 key** | 用戶永遠見唔到 |

L2 加 L3 合起嚟嘅效果：原始 key 呢種 bug **喺結構上唔可能出現**，因為 (a) 每條被引用嘅 key 都證明過存在於 en，(b) 就算 zh 冇，都係 fallback en。

**zh-HK 覆蓋率係報告，唔係 gate**（跟你「未譯自動 fallback 英文」嘅規則）：一條 test 印出「第一階段 8 個檔案 zh 覆蓋 X%」同未譯清單，但**只有** zh 值係空字串 `''`（會 render 空白）先 fail。

**L4 人眼（#36）：** `mock/` 個 renderer 可以用 zh render 四頁出圖睇闊度；字體要真機。

## 8. 語言切換嘅資料流

```
首次開 app（未有 users.language）
  → navigator.language 以 'zh' 開頭？ zh-HK : en
  → 寫入 users/{uid}.language（之後以呢個為準，換機都記得）

Profile 頁「Language」卡：English ／ 繁體中文
  → setLang() 即時 re-render（context），唔使 reload
  → 同時 updateDoc(users/{uid}, { language })
```

- **Firestore：** `users.language: 'en' | 'zh-HK'`，要加入 self-update 白名單 + rules test。（2026-07-29 `intakeCompleted` 就係漏咗白名單、runtime 靜靜雞 fail、冇人知 —— 呢次一開始就有 test）
- **教練學生獨立：** 天然如此，設定喺各自嘅 user doc
- **第一階段教練維持英文：** Language 卡**只顯示俾學生**；教練 doc 冇 `language` 就當 en。Schedule/Profile 呢啲共用頁面，教練用嘅時候 lang = en，見到嘅同而家一樣，一個 pixel 都唔會變
- **未登入頁面**（Login / RoleSelect，如果納入）：用瀏覽器語言，冇得揀 —— 揀完登入先儲
